### Three Layers of the AI Stack

1. **Application Development.** Providing a model with good prompts/prompt engineering and necessary context. Requires rigorous evaluation and sometimes can require good interfaces.
2. **Model Development.** Dataset engineering and creation/providing of tooling for models.
3. **Infrastructure.** Model serving, data management, computation and monitoring.

***Pre-Training.*** Training a model from scratch. In LLMs, this often involves training the model for text completion. This step takes a very long time to do and can incur a significant loss and setback for the project resource-wise.

***Post-Training.*** Training a model after the pre-training phase. Post-training and fine-training can be used interchangeably but sometimes people might use them differently.

***Dataset Engineering.*** Curating, generating and annotating the data needed for training and adapting AI models. Prior to LLMs, most use cases were close ended as the model could only output predefined values. In foundation models these are open-ended and can provide a wider range of responses. The setback in foundation models is that it's a bigger challenge due to its scope.

***Prompt Engineering.*** Getting AI models to express desirable behaviours from the input alone without changing model weights. It's less about giving the model a specific prompt but giving it the context and tools it needs to do a specific task.

#### Sampling Strategies. 

Some strategies makes the model's replies more creative.

***Temperature.*** Before choosing the next word, the model adjusts word probabilities using the temperature setting. Temperature controls how random the model's output is and typically ranges from values of 0 to 2.
- High Temperature: Flattens the property distribution and allows less likely words to appear more often. Increases creativity but reduces accuracy.
- Low Temperature: Favours high-probability words, produces stable and predictable text.

***Top-K Sampling.*** Limits the model to choosing the next word from only the 'K' most likely options and ignores all other possibilities. This controls randomness by focusing on higher-probability words. This reduces the computation workload without sacrificing too much of the model's response diversity.

***Top-P Sampling.*** Also known as nucleus sampling, this allows for more dynamic selection of values to be sampled from. The model sums the probabilities of most likely next values in descending order and stops when the sum reaches 'p'. For example, if you set the 'top-p' value in a model to 0.9, it will only consider the smallest set of values (most likely words) whose cumulative probability exceeds 90%.

***Max Tokens.*** The amount of tokens you want the model to respond with in order to reduce costs.

***Stopping Condition(s).*** An autoregressive model generates sequences of tokens by generating one token after another. It takes more time to response with long outputs and can sometimes be annoying. 
1. An easy method would be to ask a model to stop after a fixed number of tokens but this could lead to stopping mid-sentence. 
2. You could instead ask it to stop after encountering an end-of-sequence token.
The downside of stopping early is if you need a specific format, premature stopping can cause outputs to be malformed such as missing closing brackets on JSON or HTML files.
